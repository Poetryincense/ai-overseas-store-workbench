# P1-07 — Project Workbench UI

**优先级**：P1  
**估算**：1–1.5 工程日  
**依赖**：P1-03、P1-06  
**可并行**：否（统一项目路由和导航）

## 1. 目标

交付多项目管理的主要 UI：项目列表、创建、详情、编辑、激活/暂停、归档和恢复。工作台管理界面使用简体中文。

## 2. 输入文件（先读）

- Workbench App Router、受保护 Layout、导航组件
- Auth Session/UI Data Fetching 封装
- Project API/OpenAPI/DTO
- 现有 UI 组件库和样式 tokens

## 3. 修改范围

页面：
- `/projects`：项目列表、搜索、状态和类型筛选、分页、空状态；
- `/projects/new`：创建项目表单；
- `/projects/[projectId]`：项目详情/概览；
- `/projects/[projectId]/settings`：基础资料编辑（可以合并在详情页，但必须有清晰编辑入口）。

创建表单字段：
- 项目名称（必填）；
- 项目类型：单品验证型 / 垂直品类品牌型；
- 商业想法（必填）；
- 目标市场（可选）；
- 预算金额、币种（可选）；
- 商业模式、项目目标（可选）；
- 项目描述（可选）。

详情展示：名称、类型、状态、初始想法、目标市场、预算、商业模式、创建/更新时间。状态操作使用确认弹窗。

## 4. 禁止事项

- 不得在 UI 中硬编码项目或统计数据。
- 不得让前端直接访问数据库。
- 不得在客户端维护一套与服务端冲突的项目状态机。
- 不得展示未实现的 AI 团队、Shopify、销量或运营功能为可点击功能。
- 不得把 Workspace ID 暴露为用户可编辑字段。
- 不得在项目切换时沿用上一个项目的陈旧详情数据。

## 5. 实施步骤

1. 建立项目导航和列表页面。
2. 对接分页、筛选、搜索 API。
3. 建立创建表单和字段校验。
4. 建立项目详情与编辑表单。
5. 实现归档/恢复/状态动作。
6. 建立 loading、empty、error、success 状态和基本可访问性。
7. 编写 UI 单元测试和 Playwright 页面测试。

## 6. 验收标准

- [ ] 项目列表只展示当前用户可访问项目。
- [ ] 空项目时显示真实空状态和创建入口。
- [ ] 可以创建两种项目类型。
- [ ] 创建缺必填字段时给出清晰提示。
- [ ] 详情、编辑、归档和恢复可用。
- [ ] 操作成功后列表/详情状态刷新一致。
- [ ] 网络错误和 API 401 有明确处理。
- [ ] 无伪造功能按钮。

## 7. 验收命令

```bash
pnpm --filter @workspace/workbench test
pnpm test:e2e -- projects.spec.ts
pnpm lint && pnpm typecheck && pnpm build
```

## 8. 手工验证步骤

1. 登录后打开项目列表，确认真实空状态。
2. 创建 Project A（单品验证型）和 Project B（垂直品类品牌型）。
3. 分别进入详情，核对商业想法和类型。
4. 修改 A 的资料，确认 B 不变化。
5. 暂停、归档、恢复项目，确认状态和提示正确。
6. 使用浏览器后退/刷新，确认不会串项目数据。

## 9. 输出

项目列表、创建、详情、编辑界面及页面测试。
